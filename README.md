# לוח האימונים של שגית

אתר אישי למעקב אחר אימוני כוח: בחירת אימון מתוך רשימה, מילוי משקלים/חזרות/עומס
בסוף כל אימון, וצפייה בהיסטוריה. עברית, RTL, מותאם בעיקר לשימוש מהטלפון.

## מבנה הפרויקט

כל קבצי האתר יושבים תחת `docs/` (כדי ש-GitHub Pages יוכל להגיש אותם ישירות,
בלי שלב בנייה או Actions — ראו "פרסום האתר" למטה):

- `docs/index.html` — לוח הבית: רשימת האימונים לבחירה + סיכום קצר.
- `docs/workout.html?id=workout-1` — טופס מילוי אימון (משקל/חזרות/עומס לכל תרגיל).
- `docs/history.html` — היסטוריית האימונים שתועדו, לפי אימון.
- `docs/js/data.js` — תוכן האימונים (התרגילים, קבוצות שרירים, וכו').
- `docs/js/firebase-config.js` / `docs/js/firebase-init.js` — חיבור למסד הנתונים המשותף.
- `docs/css/tokens.css`, `docs/css/dashboard.css` — מערכת העיצוב ("soft sky") שסופקה.
- `docs/css/rtl.css`, `docs/css/site.css` — התאמות RTL ורכיבים ייעודיים לפרויקט הזה.

## למה צריך Firebase, ומה זה עושה

שגית תזין נתונים מהטלפון, ובקרה/צפייה תתבצע גם מהמחשב. אחסון בדפדפן בלבד
(localStorage) לא משותף בין מכשירים בשום צורה — לכן יש צורך במסד נתונים
משותף שכל המכשירים ניגשים אליו. האתר בנוי כך שהוא **עובד לגמרי בלי Firebase
מוגדר** — אפשר לגלוש בו ולראות את רשימת האימונים — אבל **שמירה וטעינה של
נתוני אימונים דורשות** את ההגדרה החד-פעמית הבאה.

## הגדרת Firebase (חד-פעמי, כמה דקות)

1. גשי ל-<https://console.firebase.google.com> והתחברי עם חשבון Google.
2. "Add project" → תני שם לפרויקט (לדוגמה `sagit-workouts`) → המשיכי עם
   ברירות המחדל (אין צורך ב-Google Analytics).
3. בתוך הפרויקט: **Build → Firestore Database → Create database** →
   בחרי מיקום קרוב (למשל `eur3`) → מצב **Test mode** (זמין ל-30 יום; אפשר
   להחמיר הרשאות אחר כך אם רוצים).
4. **Build → ⚙ Project settings** (או סמל הגלגל ליד "Project Overview") →
   גללי למטה ל"Your apps" → לחצי על סמל ה-Web `</>` → תני שם לאפליקציה
   (לדוגמה `sagit-web`) → **Register app**.
5. Firebase יציג אובייקט קונפיגורציה שנראה כך:
   ```js
   const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "sagit-workouts.firebaseapp.com",
     projectId: "sagit-workouts",
     storageBucket: "sagit-workouts.appspot.com",
     messagingSenderId: "...",
     appId: "...",
   };
   ```
   העתיקי את הערכים האלה ושלחי אותם לי (או ערכי בעצמך את הקובץ
   `docs/js/firebase-config.js` והחליפי את כל ה-`"REPLACE_ME"` בערכים המתאימים).

זהו — לא צריך להתקין שום דבר, אין עלות (במסגרת השימוש האישי הזה נשארים
בנוחות בתוך המסגרת החינמית).

## פרסום האתר (GitHub Pages)

הכל כבר מוגש מתוך תיקיית `docs/` (בלי שלב בנייה, בלי GitHub Actions —
פוש רגיל לענף מספיק). כדי לקבל קישור חי:

1. ברפו הזה ב-GitHub: **Settings → Pages**.
2. תחת "Build and deployment" → Source: **Deploy from a branch**.
3. Branch: לבחור את הענף הרלוונטי (למשל `main`, אחרי מיזוג) → Folder: **`/docs`**.
4. שמירה — GitHub ייתן קישור בפורמט
   `https://<username>.github.io/momworkouttracker/` תוך דקה-שתיים.

**שימו לב לקאשינג**: GitHub Pages ודפדפני טלפון שומרים קבצים במטמון בצורה
אגרסיבית. כל קובצי ה-CSS/JS כבר טעונים עם `?v=2026-09-26-1` בסוף השם כדי
להתמודד עם זה — בכל פעם שמעדכנים CSS או JS, יש להעלות את המספר הזה בכל
התגיות שמפנות לקובץ שהשתנה (ב-`index.html`, `workout.html`, `history.html`),
אחרת גרסה ישנה עלולה "להיתקע" אצל שגית גם אחרי פוש חדש.

## מה כבר נעשה, ומה עוד נשאר

בוצע: סקירת שרירים מתפספסים לכל אימון (עם השלמות לשוקיים/ביצפס שלא היו
מכוסים כלל), 2 תרגילי ליבה + מתיחות מותאמות בסוף כל אימון, וקישור הדגמה
ביוטיוב לכל תרגיל — הכל ב-`docs/js/data.js`.

נשאר:
- **תרגיל אחד ב-workout-3** ("סטפ אפ בפלאנק קדימה עם רגל על משוקולת") —
  לא נמצא לו קישור הדגמה מתאים בחיפוש; מסומן עם הערה בקוד. כדאי לצלם הדגמה
  עצמאית, או לוודא מול שגית שהבנת התרגיל נכונה ואז לחפש שוב.
- **משקלי ייחוס** — כרגע אין היסטוריית משקלים; לאחר כמה אימונים מתועדים
  אפשר להוסיף גרפי התקדמות (יש כבר `docs/js/chart-helpers.js` מוכן לכך).
- **הגדרת Firebase** ו**הפעלת GitHub Pages** — שני הצעדים היחידים שנשארו
  ממש בידיים שלכם, מפורטים למעלה.
